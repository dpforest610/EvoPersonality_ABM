- 決定時点:**本番データ(進化結果・確証的結果)を見た後**。ただし下記「確証的結果への影響」のとおり、

  結果が出るように調整したものではない。

## 背景

`docs/MARKOV_STRUCTURE_EVOLUTION_DESIGN.md`2.3.1節(2026-10-16確定)では、Gradualの罰の長さの
更新規則を「罰の最中の相手の裏切りも含めて、裏切りの累計回数を**残りの罰に足す**」(`punish_remaining +=
state["defection_count"]`)と定めていた。これは人の実験(GRA条件)の記録を実際に見ないまま、
Beaufilsら(1996)の原論文の記述から類推して決めたものだった。

その後、本報告の前段(`docs/MARKOV_STRUCTURE_EVOLUTION_RESULTS.md`4節)の探索的調査で、
GradualAppeasementの記述値がGradual(なだめなし)と常に一致するという実装バグ(なだめ中の分岐と
通常時の分岐がどちらも`COOPERATE`を返す)を発見・報告した。これを受けてユーザーが、人の実験
(GRA条件、N=171)の実際の記録を使って、罰の数え方そのものが正しいかどうかを追加で検証した。

## 検証結果(ユーザーによる、人の実験データを用いた検証)

人の実験のGRA条件の対戦記録(N=171人)に対し、3通りの罰の数え方の規則でコンピュータ側Gradualの
手を再現し、実際の記録との一致率を比較した(人のデータそのものはこのリポジトリには含まれない):

| 規則 | 手の一致率 | 全手が完全一致した人数 |
|---|---|---|
| 罰の残りに新しい累計回数を**足す**(2.3.1節で確定していた現在の実装) | 99.2% | 155 / 171 |
| 新しい裏切りを見たら、罰の残りをその時点の累計回数に**数え直す**(= 足さずに置き換える) | 99.8% | 169 / 171 |
| 罰の最中の裏切りは累計回数に**数えない** | 93.5% | 80 / 171 |

**結論:人の実験のGradualの罰は「数え直す」規則に最もよく一致する。** 2.3.1節で確定していた
「足す」規則は、人の実験データと照らすと誤りだった。

## 方針(本番データの再分析前に記録)

1. **確証的仮説(H1〜H3)への影響:なし。** H1(TFT)・H2(AllD)・H3(AllC)はいずれもGradualを
   使わないため、この逸脱は`docs/MARKOV_STRUCTURE_EVOLUTION_RESULTS.md`1節の確証的結果の
   判定・p値・Holm補正の結果を一切変えない。
2. **主セットのGradual(なだめなし)を「数え直す」規則に修正する**:
   - 報復は相手の裏切りを見た次の手から(変更なし、TFTと同じ参照方式)。
   - 裏切りの累計回数は、罰の最中に見た裏切りも含めて対戦開始から数える(変更なし)。
   - **新しい裏切りを見るたびに、罰の残りをその時点の累計回数に置き換える(足さない)**
     (変更点。例:1回目の裏切りの罰の最中〜直後に2回目・3回目と裏切りが続いた場合、
     「足す」規則では罰の残りが実際より長くなってしまうが、「数え直す」規則では常に
     その時点の累計回数と一致する)。
3. **GradualAppeasementをBeaufilsら(1996)の原版どおりに修正する**:
   - 罰が終わったら、相手の手にかかわらず**必ず2回協調する**(なだめの途中の相手の裏切りで
     なだめを打ち切らない — 現在の実装の「なだめ中の裏切りは即座になだめを中断し罰を再開する」
     という挙動も、原版とは異なる独自の誤りだったため合わせて修正する)。
   - なだめの途中に見た裏切りは、裏切りの累計回数には数える(無視はしない)が、罰はなだめが
     終わった後に、その時点の累計回数で(数え直す規則で)始める。
4. **進化(evolution)はやり直さない**。本番の主条件・感度分析の進化ラン(population評価)は
   Gradualの罰の規則を直接使っておらず影響を受けない(Gradual/GradualAppeasementは進化の
   適応度計算ではなく、固定戦略としてのプローブ[probe]でのみ使われる)。Macにある各プローブ
   時点のgenotype census(`seed_X_probe_age_G_census.csv.gz`、進化で実際に生まれた遺伝子型の
   一覧)を使って、**Gradual・GradualAppeasementに対するプローブだけをやり直す**(census自体は
   再生成しない、他のオポネント[TFT/AllC/AllD/Random/WSLS]のプローブ結果も変更しない)。
5. **修正前の値も並べて報告する**(事前登録8節の指示どおり)。`docs/MARKOV_STRUCTURE_EVOLUTION_RESULTS.md`
   の該当箇所(6-7節、4節のGradualAppeasement調査)を、修正前・修正後を併記する形に更新する。
