# 逸脱：K-恐れ型の系統間抽出の人数（事前登録 3節）

- 対象：`docs/PREREGISTRATION_k_model_markov.md`（確定コミット `82203334`）3節「群の作り方」
- 決定：2026-10-26、安念。**確証的な分析の結果（相関、回復率、p 値）を一つも見る前に決定した。**
  決定の材料にしたのは、各時点・各 seed にどの類型の個体がいるか（census の K の値だけ）であり、
  仮説に関わる量は計算していない。

## 1. 事前登録の記述

3節：系統間抽出を主分析とし、K-安定型は56、合成 Mix は46、K-恐れ型は69の **別々の seed**
から1体ずつ選ぶ。「70 seed あれば人の群の人数（56・46・69）のどれでも distinct seed の本数を
満たせる」。

## 2. 何が起きたか

この記述は「どの時点でも、どの seed にもどの類型の個体がいる」ことを暗に前提にしていた。
本番データ（seed 200〜269、gen 1000〜5000 の81時点）で、各時点にその類型の個体が1体以上いる
seed の数を数えると：

| 群 | 必要な seed 数 | 足りない時点 | 最少 |
|---|---|---|---|
| K-安定型 | 56 | 0 / 81 | — |
| 合成 Mix | 46 | 0 / 81 | — |
| K-恐れ型 | 69 | **60 / 81** | 63 |

K-恐れ型は多くの時点で69 seed に届かず、事前登録どおりの抽出は **実行不能**（確証的分析の
スクリプトは `ValueError: group_size=69 exceeds available seeds=68` で停止した）。

## 3. 変更（安念の決定：案 (a)）

その類型の個体がいる seed の数が人の群の人数より少ない時点では、**いる seed すべてから1体ずつ**
選んで群を作る（群の人数 = min(人の群の人数, その類型がいる seed の数)）。系統間抽出の考え方
（1つの系統から1体）はそのまま守る。K-恐れ型では、群の人数は時点によって63〜69になる。

同じ規則を、次のすべてに一貫して適用する：

- 5-1節の点推定（1000回の抽出）。
- 5-2節の seed ブートストラップ：復元抽出した70の位置のうち、その類型の個体がいる seed の位置
  だけから選ぶ（人数 = min(人の群の人数, その位置の数)）。変更前のコードでは、類型のいない
  seed の位置が選ばれると空の集団から抽出しようとして止まる不具合もあった（K-安定型・Mix でも
  起こりえた）。これも同じ規則で解消する。
- 5-4節の置換検定：ラベルは各 (seed, 時点) の中で入れ替えるので、各類型がいる seed は本物の
  ラベルと同じであり、群の人数も同じになる。本物のラベルの統計量（50回の抽出）も同じ人数で計算する。

各時点・各群で実際に使った人数は、時点ごとの結果に `ha_effective_group_size` として記録し、
結果の報告に添える。

## 4. 検討して採らなかった案

- (b) 足りない分を、すでに選んだ seed からもう1体選んで補う：人数は人の群と同じに保てるが、
  同じ系統から2体入り、系統間抽出の考え方から外れる。
- (c) 人数が足りない時点を、その群について H-A の計算から外す：K-恐れ型では81時点中60時点が
  外れ、時間窓の平均が群ごとに違う時点の集まりになる。

## 5. 「元の計画どおりの結果」について

事前登録8節は、逸脱のときに元の計画どおりの結果も並べて報告するとしている。今回は元の計画が
60時点で実行不能なので、元の計画どおりの結果は存在しない。代わりに、足りなかった時点と人数の
一覧（上の表と `ha_effective_group_size`）を報告する。
